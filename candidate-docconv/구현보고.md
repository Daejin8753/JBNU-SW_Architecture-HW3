## 7. 지시에 없어서 직접 정한 것

1. `plugins.json` 이 없는 첫 시작에는 plugins/ 의 모든 파일을 install 시도한다(이후에는 `active` 만 적재). `future_contract` 는 이때 rejected 가 된다.
2. 같은 형식 변환기 중복은 시작 적재에서도 같은 규칙: 이름순으로 먼저 적재된 쪽이 active, 나중 것은 `available` + 사유(409 메시지).
3. plugin_host 는 `sys.stdout` 대신 fd 수준에서도 1번을 2번으로 돌린다(C 라이브러리 출력이 프로토콜을 깨지 않게).
4. "PyMuPDF 없음" 은 `pdf_conv` 의 `ImportError("PyMuPDF 없음")` → plugin_host `ready: false` → `rejected`("자식 기동 실패: ImportError: PyMuPDF 없음"). 적재 중 예외는 모두 `LoadError("자식 기동 실패: ...")` 로 바꾼다.
5. 생명주기 오류용 code `not_found`(404), `conflict`(409). 입력 계약 위반과 알 수 없는 op 는 `rejected`.
6. 안전 검사·형식 판별을 inspector 의 op 두 개(`check`, `detect`)로 나눴다. `check` 는 업로드 20MB 상한도 다시 본다.
7. 텍스트 판정: NUL 이 있으면 텍스트 아님, 그다음 utf-8(BOM 포함) → cp949 디코딩.
8. HTML 태그 판별 목록: `<!doctype html`, `html`, `head`, `body`, `p`, `h1~h6`, `div`, `table`, `ul`, `ol`, `br` (앞 1KB, 대소문자 무시).
9. 실패한 변환도 기록에 남긴다. 실패 기록 사유는 `"<code>: <message>"`, 저장 실패는 `"internal: 저장 실패[, 파일 정리 실패]"`.
10. 저장 ID 는 코어(flow)가 만들어 storage 에 넘긴다. storage 는 ID 형식을 다시 검사한다. 성공 기록(`record`) 실패도 저장 실패와 같이 처리한다(파일 정리 + 실패 기록 시도).
11. 내려받기 이름은 표시 이름의 확장자를 `.md` 로 바꾼 것, ASCII 대체 `filename="download.md"` 도 넣는다. 내려받기 응답은 JSON 이 아니라 trace_id 를 `X-Trace-Id` 헤더로만 준다.
12. trace_id 는 `token_hex(4)`, `/api/trace/{id}` 는 `^[0-9a-f]{8}$` 만. `/api/trace` 조회 자체와 그 limit 오류는 기록하지 않는다.
13. 코어에 닿기 전에 거부한 요청(403·411·413·모르는 `/api/` 경로 404)의 hop 은 `client → http_adapter`, op 는 오류 code, ok false.
14. XML 선언 encoding 은 대소문자 무시로 `utf-8` 만 받는다(`utf8` 도 거부). 선언이 없으면 UTF-8 로 본다.
15. 깊은 중첩 hwpx 는 `RecursionError` 를 `Rejected("손상된 문서")` 로 바꿔 400 이 된다(지시서는 400 또는 200 허용).
16. 후처리 결과 크기 초과 경고의 code 는 `rejected`, message 는 "결과가 20MB 를 넘음". 모르는 후처리기 이름은 40자에서 잘라 오류 메시지에 넣는다. `X-Post` 의 이름 정규식 검사는 없앴다(레지스트리 조회로 400).
17. 경고는 `{plugin, code, message}` dict 다. UI 는 `warnText` 로 한 줄로 보인다.
18. `requires` 위반은 정적 검사 결과에 줄 번호 1 로 넣는다(MANIFEST 위치를 따로 찾지 않음).
19. `check_values` 의 깊이 초과(`RecursionError`)는 출력 위반으로 본다. 허용 컨테이너는 `list`·`dict`(str 키)만, `tuple`·`set`·`bytearray` 는 위반.
20. PDF 출력: 쪽마다 `<!-- page N -->`, 쪽 사이 `---`. 쪽 0개면 손상된 문서. docx 제목 스타일은 `Heading1~6`·`제목 1~6`. hwpx 는 지역 태그 이름으로 맞춘다.
21. frontmatter 값은 JSON 문자열, converted_at 은 지역 시간대 ISO 8601. whitespace_post 는 빈 줄을 최대 2줄 연속으로 줄이고 앞뒤 빈 줄을 지운다.
22. 시험 fixture 를 추가로 만들었다: hold_conv, not_subclass(·_proc), reject_post, ext_a·ext_b, values_inproc·values_proc, manifest/ 20개, violations/ 에 v_req_os·v_req_internal. 시험 쪽 장벽은 `tests/helpers.py:Barrier`.
23. `tools/make_samples.py` 의 `small_size_docx` 는 선언 크기와 함께 CRC 를 앞 40바이트에 맞춰, B "ZIP 안전 열기" 문장(잘린 XML → 변환기에서 손상된 문서)을 실제로 재현한다.

## 8. 못 한 것·모르는 것

- 브라우저 조작 확인은 하지 않았다(메인 에이전트·사용자 몫). UI 는 정적 파일 200 과 경고 표시 함수(`warnText`)만 고쳤다.
- PyMuPDF 가 실제로 없는 환경의 `PdfWithoutPyMuPDF` 는 이 PC 에서 건너뛰어 직접 돌지 않았다. 같은 기동 실패 경로를 `missing_pkg` fixture 로 시험했다.
- 시험 시간은 약 26초다(E3·E8 의 시간 초과 대기 포함).
- 구현 2차 교차 검토에서 고치지 않기로 한 것: NIT 1·2·5~8, 판단 필요 2건(plugins.json 없는 첫 시작과 rejected 비저장, 압축 방식 검사 대상 항목). 지금 동작을 한계로 남긴다.
