## 단순화 (8판 → 9판)

- 기준: 과제의 중심(코어·레지스트리·계약·커넥터, 코어 경유 제약, 품질 문제)이 아닌 장치 가운데, 시험 순서를 맞추려고 생겼거나 신뢰 범위(로컬 개발자) 안에서 필요 없는 것을 줄인다. 보안 장치(출처 검사, 파일 이름 정리, DOCTYPE 거부)와 품질 측정은 남긴다.

| 줄인 것 | 바꾼 규칙 | 이유 |
|---|---|---|
| 별도 프로세스: `child_epoch`·`waiting`·호출 진입 기준 deadline | 잠금은 시간 제한만큼 기다리고(못 얻으면 503, 장애 아님), 잠금을 얻은 뒤 시간 제한을 새로 잰다 | 4~6차 지적은 "기다리던 정상 요청이 남은 시간 부족으로 재기동에 실패해 장애로 세어지는" 문제였다. 시간을 나누면 그 문제가 생기지 않는다. 번호 장치와 시험용 값 2개가 필요 없어진다 |
| E8 의 3단계 동기화(`waiting`=2, epoch 확인) | hang 1개 + 일반 요청 2개. 일반 요청은 성공 또는 503 이면 된다 | 위 규칙에서는 어느 순서로 와도 실패 수가 1이다 |
| 쓰기 스레드, 응답 32MB 상한, stderr 비우기 스레드 | 쓰기는 요청 스레드에서 바로. stderr 는 버리고 import 실패는 준비 응답 `{"ready": false, "error"}` 로 받는다 | 한 번에 한 요청만 보내므로 살아 있는 자식에 쓰기가 막히지 않는다. 플러그인 작성자는 신뢰 범위 안이다 |

| 지적 | 처리 | 위치 |
|---|---|---|

| R10-H2 바이트 태그가 일반 dict 와 충돌 | 키가 `$b64`·`$esc` 하나뿐인 일반 dict 는 `{"$esc": ...}` 로 감싸는 이스케이프 규칙. 쓸 수 있는 값의 종류를 정하고, 출력 계약 검사가 두 runtime 모두 그것을 본다. 왕복 시험 추가 | 공통 "별도 프로세스" 프로토콜 |
| R10-H3 CSV 입력 오류가 장애로 셈 | `csv.Error` 를 `Rejected` 대상에 넣음. 긴 필드 CSV 3회 시험 추가 | B "확장점 op", "추가 시험" |

- 판 번호: `공통.md` 13판, `A-경매.md` 6판, `B-문서변환.md` 7판.
